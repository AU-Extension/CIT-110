PowerShell vs Bash pipeline visualizer

A pipeline sends the output of one command into the next with the | symbol. Build pipelines from blocks and watch what travels between the commands: whole objects with properties in PowerShell, plain lines of text in Bash.

How to use this interactive
  1. Pick PowerShell (Windows) or Bash (Ubuntu), or load one of the ready-made pipelines.
  2. Click blocks to add them to your pipeline. The first block is always a command that produces data.
  3. Press Run all to see the output after every stage, or Step to move one command at a time.
  4. Compare the blue object tables (PowerShell) with the yellow text lines (Bash). That difference is the main lesson.
  5. Try breaking things on purpose, for example filtering processes by a property they do not have, and read the explanation.

Why this matters

Because PowerShell passes objects, you can sort by a property even if you never see it on screen. Bash passes text, so you must know which column holds the value and remember that the header line is text too.

When an AI assistant writes a pipeline for you, run each stage on its own first (this tool does exactly that). If a stage returns nothing, the stage before it is usually where the mistake is.

Commands on this page only read or display data, and the one that saves writes a new file. Week 7B shows pipelines that end in commands that delete or change things. Those need much more care.
